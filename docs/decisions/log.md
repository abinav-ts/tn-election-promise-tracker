- **D-029 · 2026-10-08 · Only definitive failures are `fetch_failed`; temporary ones stay pending.** The first full crawl marked ~2,380 GOs as failed after one connection drop on cms.tn.gov.in, and deferred 1,363 Wayback items after one throttle, because a single failure paused a host for the whole run. - **D-030 · 2026-10-09 · Downloads have a time limit and PDFs must be complete.** One Wayback capture took 3.5 h, and a CAG file was a truncated 5 MiB capture with no `%%EOF`. Downloads are streamed and aborted after `http.max_download_s` (600 s), as a retryable failure listed in the coverage gaps. A PDF is kept only if it has `%%EOF` at the end and opens in PyMuPDF. A truncated Wayback capture is not a "newer version" under D-018: the latest complete capture is kept, else a fetch failure. Incomplete files already stored are quarantined (moved, not deleted) and fetched again, an exception to raw-file immutability.
- **D-031 · 2026-10-09 · Crawl order: live sources first, slow Wayback-only sources last** (S1 → S2 → S6 → S7 → S3 → S4 → S5), so a slow archive download can't hold up the GOs and scheme pages.
- **D-032 · 2026-10-11 · Listing date vs. the document's own issue date: the later one wins.** In the full run ~6 GOs were dated 9–13 days after their listing date; using the listing date would make them visible early in cutoff runs. Applies only to a day-precise text date; the usual case (GO dated before its listing) is unchanged. Full corpus: 49 GOs use the later date, 7 of them probably because OCR misread the year (later, never earlier, so no leak).
